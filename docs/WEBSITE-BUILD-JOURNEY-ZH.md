# Ryan Zhao 工程作品集网站：从零到当前的建站记录

> 本文依据项目 Git 提交、`PLANS.md`、`docs/` 中的实施/验收记录，以及本机 Codex rollout 会话元数据整理。它记录到 **2026-09-28**。日期与结果只在有仓库或会话证据时写入；设计目标、已部署代码、内容发布和备份验收分别描述。Codex 会话原件留在本机，本文不是会话逐字导出。

## 1. 项目从哪里开始

项目目标是制作 Ryan Zhao 的工程作品集：让访客看到个人介绍、工程项目、实验/制作过程，并能在桌面和手机上浏览。网站设计最初以 Canva 页面为视觉参考；随后范围逐步扩展到受保护的内容后台、媒体上传和处理、页面可视化编辑、私有预览，以及经审核后分开部署代码和发布内容。

2026-09-19 的项目计划记录：先检查目标目录，确认它是空的；同时发现父目录 Git 配置指向不相关的 DIY-Drone-resources 仓库，因此为作品集单独建库，没有复用错误远端。检查了当时本机 Node/npm 与 Next/OpenNext/Wrangler 的兼容性，也找到已有 Windows `Codex Conversation Archive` 计划任务，决定复用而不另造一个。随后确认已有 Sanity 与 Cloudflare 账户/项目；新建云资源、付费、域名迁移和首次公开发布都按阶段另行授权。

## 2. 采用的技术与平台

| 部分 | 当前采用方式 | 作用与边界 |
|---|---|---|
| 网站应用 | Next.js App Router、React、严格 TypeScript、Tailwind CSS | 页面、组件、管理界面与 API；本地与生产构建共用应用代码。 |
| Cloudflare 运行时 | OpenNext、Cloudflare Workers、Wrangler | 将 Next 应用适配并部署到 Workers；本地 Workers 预览用于检查 Cloudflare 运行行为。 |
| 内容与管理 | Sanity Content Lake / Studio | 管理结构化内容。Studio 是编辑界面；登录、发布权限和内容校验由独立的安全边界控制。 |
| 媒体与任务 | Cloudflare R2、D1 | 原始素材、已发布衍生媒体和私有备份分开存放；D1 保存上传/处理等运营状态。 |
| 本地模型/媒体处理 | 用户自己的 Windows PC、Node 处理脚本；STEP 转换依赖 CadQuery/OpenCascade | 大型 CAD 原件留在私有流程中，由 PC 下载和转换，生成可浏览 GLB。访客读取已发布衍生文件不依赖 PC 在线。 |
| 设计与验收 | Canva 参考页、Chrome/浏览器检查、Node 测试、Workers 本地 smoke | 设计参考与代码验收。截图和临时测试素材在忽略目录，不作为公开仓库内容。 |
| 版本记录 | 私有 GitHub `ryan-portfolio-archive`，功能分支 `codex/...` | 保存代码和项目文档。内容发布、Cloudflare Worker 部署、网站备份不是 Git 提交的同一件事。 |
| AI 协作 | Codex Desktop + 本地仓库/终端/浏览器工具 | 读取规格和本地证据、分段实现、运行适当验证、核实实际部署/浏览器状态、记录限制，再按项目规则提交。原始 Codex 历史另存于本机，并由已有独立归档任务处理。 |

实际依赖版本以 `package.json`、`package-lock.json` 和 `.node-version` 为准；不要把表格理解成始终最新的上游版本。Cloudflare 与 Sanity 配置、账户计划、已部署版本均可能变化，复用时需先读回当前状态。

## 3. 实施过程

### 阶段 A：先搭本地应用骨架（2026-09-19）

先完成 Next.js / OpenNext 项目结构、响应式基础页面、草稿项目内容、管理状态页、noindex/预览边界、健康检查和 Workers 本地配置。建立 lint、TypeScript 检查、Node 测试、OpenNext 构建和 Workers HTTP smoke 的验证路径。此时明确：本地页面能运行不代表已连接 CMS、媒体存储、身份服务或生产站点。

早期 Workers smoke 曾出现软 404/流式边界问题；通过移除造成软 404 的 loading 边界、重跑路由检查解决。Windows OneDrive 云重解析目录曾使 Next 清理构建目录遇到 `EPERM`；保留旧生成物作恢复证据后完成干净构建，没有移动项目原件。检查结果和限制记入 `docs/VERIFICATION.md`。

### 阶段 B：复刻 Canva 视觉，保留真实素材空位（2026-09-19）

浏览器检查 Canva 参考页的桌面与手机布局，记录黑色首页、衬线大标题、米白介绍区、橙色强调、三条项目时间线和五个主题栏目。实现首页与五个栏目页、响应式导航、键盘交互及移动端纵向时间线。因为没有可确认的原始照片、Logo 图稿和字体身份，保留标记清楚的照片位；Georgia 与文字 MARS 标记只是替代，不宣称像素级复刻。没有生成或抓取实验照片，没有补写未经证实的经历/成果。

当时对六个页面在 390、768、1024、1440、1920px 做浏览器视口检查，共 30 个检查画面；修复平板宽度内容溢出。Workers 本地 smoke、noindex 与未知路由检查通过。具体边界见 `docs/DESIGN-REFERENCE.md` 与 `docs/VERIFICATION.md`。

### 阶段 C：把后台从“状态页”逐步做成可用编辑工作流（2026-09-19 至 2026-09-21）

按先身份、后数据写入的顺序实现 Access JWT 验证、管理员 allowlist、精确 Origin 检查、限流、上传会话、分片传输、媒体槽位、草稿、历史快照和恢复为草稿等能力。Sanity 提供结构化内容与 Studio；R2 将私有原件、公开衍生文件和私有备份分开；D1 记录任务与写入限制。发布必须明确确认，并校验候选页面与媒体，不由“上传”或“保存”隐式触发。

早期的本地模拟测试只证明本地实现；之后才逐项进行真实 Access、Chrome、Sanity、R2、D1 与 Worker 读回验收。云端遇到过 Sanity 返回对象键顺序变化、Workers 请求数限制、保存冲突等问题：通过规范化内容比较、分批读取和 revision/CAS 冲突保护修正。具体上线版本、测试数及操作范围按日期记录在 `PLANS.md` 和对应 `docs/`，不可把早期计划误认为最终状态。

### 阶段 D：加入画布式页面设计器与可恢复编辑（2026-09-20 至 2026-09-21）

从首页区块编辑器扩展到站点级 Canva 风格编辑器，支持共享导航、跨页草稿、元素选择/编辑、撤销、页面创建、回收与恢复、历史快照等。先写规格，再按小块实现和验证。云端读写需控制请求数；保存比较考虑 JSON 键顺序变化；遇到远端 revision 变化时保留并提示当前输入，避免覆盖并发编辑。

本地与云端 Chrome 验收分别记录。实测通过的保存、撤销、跨页读取与历史读取，和未执行的正式内容发布/全站恢复演练分开记载。完整证据见 `docs/DESIGNER-ACCEPTANCE.md`、`docs/ROLLBACK.md` 和 `PLANS.md`。

### 阶段 E：媒体素材库、上传、发布与本机处理器（2026-09-20 起）

建立统一素材库、标签与展示位置；支持上传、断点续传、私有预览、显式发布、历史恢复和失败状态保留。图片/视频上传与素材处理是不同步骤；未处理/未审核资产不能因为已上传就当成公开成品。电脑端处理器使用隔离的本机配置目录，密钥不进入仓库、命令行记录或网页；机器身份与人的管理员登录身份分离。

为模型建立 STEP/STP → Windows PC → GLB 流程，设置输入/输出大小、超时、内存与几何复杂度检查。2026-09-26 曾遇到 201 MB 级 STEP 下载中途截断和 Cloudflare Worker Free CPU 时间不足：客户端改为带版本核验的分段下载；确认 Cloudflare CPU 限制后没有把后台目录变成昂贵转换服务，也没有把失败伪装为成功。用户提供 GLB 时可直接校验并上传，省去转换。原始文件保持私有。

### 阶段 F：独立部署作品集（2026-09-28）

经用户授权，将作品集部署到独立子域名和 public Worker；用户既有主站与受保护管理 Worker 保持各自用途。发布配置仅读已发布 Sanity 内容和 R2 衍生媒体，不绑定原件、备份、D1 或管理密钥。浏览器检查正式路由、真实 GLB、图片/视频响应范围和手机宽度；保留 noindex。

代码 Worker 部署和内容发布是分开的操作。已验证的 GLB/页面发布有单独记录。2026-09-28 首页发布检查发现现有 hero 与 chemistry 图片块超出桌面区块边界，用户选择保留现状并暂缓首页内容发布；所以文档明确保留私有草稿，不能说首页已发布。后续视频画廊在私有草稿中加入并验证播放；Machining 仍是空位，因为尚未确认 Thruster 视频属于该项目。

## 4. 真实遇到的问题与处理原则

| 问题 | 处理方式 | 可复用的经验 |
|---|---|---|
| Canva 原始字体、Logo、照片不可确认 | 使用清晰标记的替代文本/素材位，记录视觉差异 | 不把临时替代品说成原件；素材来源和授权清楚后再替换。 |
| 平板页面横向溢出 | 收紧占位图宽度、调整卡片列数，再用多尺寸视口复核 | 响应式断点需要真实浏览器布局检查。 |
| Next/OneDrive 云文件导致构建清理 EPERM | 保留旧生成目录作为恢复材料，再完成构建 | 不因生成物错误去删除或移动用户原件。 |
| 上传完成与媒体可用不是一回事 | 增加私有处理状态、校验、预览与单独发布步骤 | 每个外部系统都要有可读回的状态与失败路径。 |
| Sanity JSON 键顺序导致误判内容改变 | 用规范化内容比较，同时保留 revision 检查 | 比较语义内容时避免依赖对象序列化顺序；并发写入仍需版本约束。 |
| 大 STEP 下载截断/Worker CPU 超限 | PC 分段下载并核对源版本；Worker 只协调任务；必要时上传预转换 GLB | 大文件计算放在经选择的处理端，失败保留原件且不报假成功。 |
| 设计器多个窗口同时保存 | 重新读取最新 revision，发现冲突保留对方编辑 | 不以旧草稿覆盖新状态；冲突需要明确恢复/重试。 |
| 首页内容块越界 | 阻止发布该首页，保留草稿和现有公开版本 | 发布门槛检查的是内容状态，不只是代码构建成功。 |

## 5. 当前 AI Workflow（可以复用的做法）

1. **从项目规则和批准规格开始。** 先读取 `AGENTS.md`、`PLANS.md`、相关设计规格和现有架构说明；遇到范围变更时以最新明确决定为准。
2. **先盘点现场。** 看当前分支、工作区、远端、现有云资源/页面状态和相关代码；不假定此前任务的状态还有效。
3. **把工作拆成可审阅步骤。** 先定数据流、权限和失败行为，再改实现；复用已有组件/平台功能，不先搭未来可能用不到的抽象。
4. **每种证据单独报告。** 单元/集成测试、本地 Workers、真实浏览器、云端部署、实际内容发布、备份校验是不同证据，不能互相替代。使用真实用户素材时保留原件、草稿和明确发布边界。
5. **遇到限制先定位根因。** 记录状态码、响应、版本、字节数、运行时限等；先保护已有数据，再选择最小可验证的修复。区分短暂超时、实际平台限制和内容未确认。
6. **变更后核对副作用。** 检查最终差异、无关文件、密钥/令牌、生成物和原始媒体；对重要代码/文档变更只暂存预期文件，提交后推送并验证远端 commit。
7. **记录可复用信息。** 规格、运行手册、验收事实、已知限制写进 `docs/` 与 `PLANS.md`。忽略目录里的截图/测试素材仅作为本机证据，不随源码归档。

Codex 的作用是按指令读写代码、分析日志、运行检查，并在授权的浏览器/平台范围内执行验证；它不能从本地测试推断真实账户状态，也不能代替用户批准首次公开、改变域名、付费或发布正式内容。原始 Codex 对话是另一个私有归档流程；本文只提炼项目过程，不复制会话 JSONL、认证配置或密钥。

## 6. 复用此流程建新网站

1. 新建独立目录/仓库前先检查目录、父级 Git、现有远端和已有资源，防止覆盖或复用错误仓库。
2. 收集已批准的视觉参考、真实内容、素材来源、目标设备、域名、CMS 与运行平台；未知信息标为待确认，不自动编造。
3. 先交付本地可运行页面和预览边界；根据项目需要加入 lint、类型检查、测试、目标运行时构建与路由 smoke。
4. 需要管理功能时先定义身份、数据所有权、草稿、发布和恢复策略；将原件、公开衍生文件与备份隔离。
5. 每个阶段分别验收本地、浏览器、云服务、内容发布和备份。生产动作按用户授权推进，并保留上个可用版本。
6. 将阶段记录、部署步骤、问题修复和未完成事项与代码一起维护，方便接手者重现。
